Wishlist mini-app — план реализации

2026-11-16 · для исполнителя, который не видел ни кода, ни разговора · шаги отмечаются чекбоксами (checked) прямо в этом файле

Для исполнителя: используй superpowers:subagent-driven-development (рекомендуется) или superpowers:executing-plans. Следуй шагам по порядку.

Цель: Telegram mini-app с постоянным вишлистом на дни рождения: гости бронируют и скидываются на подарки, именинник не видит броней до итогов.

Архитектура: один TypeScript-контейнер: Hono (API и статика SPA) + grammY (бот, long polling) + SQLite на volume + планировщик (курсы, бэкап). Фронтенд на Preact + Vite. Вход через Tailscale Funnel на Mac mini.

Стек: Node 22, TypeScript, Hono + @hono/node-server, grammY, better-sqlite3, zod, sharp, cheerio, undici, Preact, Vite, @twa-dev/sdk (вшит в бандл, внешних скриптов нет), Vitest, Playwright.

Спецификация: docs/superpowers/specs/2026-11-16-wishlist-miniapp-design.html (прочитать целиком до начала).

Глобальные ограничения

  • Лицензия Apache-2.0 (текст взять из /home/yinon/Projects/iris/LICENSE). Образ linux/arm64 (Mac mini), также должен собираться на amd64.
  • Один язык (TypeScript) и один контейнер. Бот на long polling. Публичный вход через Tailscale Funnel; гостям Tailscale не нужен.
  • Конфигурация только через .env: BOT_TOKEN, OWNER_ID, PUBLIC_URL, BIRTHDAY (MM-DD), CURRENCIES (по умолчанию RUB,ILS,USD,EUR), DEFAULT_CURRENCY, DATA_DIR, плюс TIMEZONE, PORT, BOT_USERNAME, APP_SHORT_NAME, BACKUP_KEEP (7), BACKUP_HOUR (3), INITDATA_MAX_AGE_SEC (86400).
  • Авторизация: подпись initData (HMAC) токеном бота и срок давности. Роль владельца определяется только на сервере по OWNER_ID.
  • Инвариант: ни один ответ API владельцу не содержит данных о бронях и взносах (ни имён, ни статуса, ни прогресса) до закрытия раунда.
  • Языки ru и en, каталоги строк с одинаковым набором ключей. Внешних запросов с клиента нет (шрифты, скрипты, картинки только с нашего origin).
  • RED-GREEN в каждой задаче: тест падает по названной причине, затем минимальный код. В том же коммите запись в CHANGELOG.md (Keep a Changelog, раздел Unreleased).
  • Деньги хранятся целым числом в минимальных единицах (priceMinor); поддерживаются только валюты с 2 знаками после запятой.
  • Git-идентичность репозитория уже задана локально. Каждый коммит оканчивается строкой Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>. Репозиторий на GitHub не создавать и ничего не пушить без разрешения владельца. В коммитах только .env.example, без реальных секретов.
  • Документы для GitHub (README, SECURITY, CONTRIBUTING, docs/) в Markdown на английском по образцу Iris (/home/yinon/Projects/iris); диаграммы и баннер в SVG.

Review Focus

Пять входов и условий, которые спецификация подразумевает, но обычные тесты их не проверят. Каждому отведён тест в задаче-владельце.

  1. Утечка броней владельцу через побочные пути: тексты ошибок, коды 409/403, правка и удаление подарка с бронью, порядок и поля списков. Владелец должен видеть абсолютно одинаковый ответ для забронированного и свободного подарка (Задачи 8, 10, 25).
  2. Подделанный или просроченный initData: нет hash, изменённое поле, auth_date из будущего или старше лимита, пустая строка. Ответ 401, без сведений о причине (Задача 3).
  3. Гонки и повторы: двойной тап «Забронировать», два гостя одновременно, два взноса, которые вместе превышают цену. Ровно один победитель, сумма взносов никогда не больше цены (Задачи 9, 25).
  4. Враждебные ссылки и файлы: редиректы и DNS на приватные адреса, схемы не http(s), HTML на сотни МБ, не UTF-8, относительный og:image; загрузка SVG, не-картинок, огромных файлов; EXIF с GPS должен вырезаться (Задачи 11, 12).
  5. Границы суток и часовой пояс: отсчёт до дня рождения в день X и сутки после, BIRTHDAY=02-29 в невисокосный год, доступность «Подвести итоги» ровно в полночь по TIMEZONE (Задачи 6, 18, 23).

Также во всех сообщениях бота имена гостей экранируются для HTML-режима, а сбой доставки (бот заблокирован) никогда не ломает основную операцию.
